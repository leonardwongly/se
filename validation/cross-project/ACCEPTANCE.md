# Frozen acceptance

Eight fresh project-specific prompts run under the same final global policy and unchanged installed skills. Evaluate each expected selection from actual installed instruction reads, delivered output completeness, and timing before corresponding work. Top-level prompts contain no skill names. Child reads must occur in their own turns; inherited parent history never counts. Primary selection and substantive application are separate criteria.

Non-code tasks must answer the exact question with current source evidence and material limits; readiness must distinguish current executed checks from future release readiness. Specialist must actually launch exactly one bounded delegate and independently check its findings. Team must actually launch two workers, use disjoint ownership, preserve boundaries, run meaningful tests and integrate only once writers finish. Visual must accurately explain all four requested paths and exercise controls in an actual preview; code inspection alone cannot pass browser behavior. Verification must reach the actual handler and demonstrate denied effects and a discriminating negative control, labeled as VM/stub evidence.

Independent team checker is designed from the frozen contract before examining implementation. It must retain before/after failures, not accept setup failures as detector sensitivity. Record environment, baseline, policy/skill hashes, source identities, commands, actual outcomes and blocked/unrun checks. No production, installation, release, reliability or universal selection claim. All eight tests must be evaluated under final policy, not coverage borrowed from earlier runs. If a policy repair is required, preserve the first full batch and repeat all eight under the repaired final policy.

Preserve primary project checkout; publish sanitized results, fresh prompts and reusable checks/patches only to the se repository. Keep raw transcripts, unrelated global config and private identifiers local.

When navigation
loses the network.

One navigation, a sequence of chances to return a response: preload → network → cached offline page → emergency 503. Each successful return ends the sequence.

Grounded in the local source at revision 4a50ea995c37132bcfee5c64fd908d35ca0cef96 Illustrative playback timing; no network request, service-worker registration or cache operation is performed by this explanation.

An HTTP error is still a response. A resolved preload or fetch response, including a 404 or 500, is returned as-is. The handler never checks response.ok or status. Only a rejected network fetch reaches the cache. pwabuilder-sw.js:92–116

Navigation only. When request.mode !== 'navigate', this listener does not call respondWith, read preload, call fetch or consult cache. Images, styles and ordinary API fetches are outside this fallback. pwabuilder-sw.js:89–120

Every path, without playback

Stages are handler decisions, not a network timing diagram. Browser preload may already be in flight before this handler awaits it. “No preload” and “rejected preload” both lead to the explicit network fetch.

Preload succeeds

  1. The request is a navigation; respondWith takes ownership.pwabuilder-sw.js:89–91
  2. Await preloadResponse. It resolves to a response.pwabuilder-sw.js:92–98
  3. Return that preload response. The explicit fetch and cache lookup never run.pwabuilder-sw.js:99–101

Preload rejects; network succeeds

  1. The request is a navigation; respondWith takes ownership.pwabuilder-sw.js:89–91
  2. preloadResponse rejects. Its own catch absorbs the failure; this does not skip the network attempt.pwabuilder-sw.js:92–101
  3. Call fetch(event.request). It resolves to a response.pwabuilder-sw.js:103–104
  4. Return the network response. The offline cache is never opened.pwabuilder-sw.js:104–105

Network rejects; cache has content

  1. The request is a navigation; respondWith takes ownership.pwabuilder-sw.js:89–91
  2. No preload response is available. A rejected preload would reach the same next step.pwabuilder-sw.js:92–101
  3. fetch(event.request) rejects. Enter the network catch and try the offline cache.pwabuilder-sw.js:103–106
  4. Open pwabuilder-offline-cache-v2 and match offline.html. A cached response exists; this is a fixed fallback page, not a cached copy of the requested URL.pwabuilder-sw.js:3, 11, 107–109
  5. Return the cached response unchanged; the handler does not assign it a 503 status.pwabuilder-sw.js:109–111

Network rejects; cache unavailable

  1. The request is a navigation; respondWith takes ownership.pwabuilder-sw.js:89–91
  2. No preload response is available, or preload rejected.pwabuilder-sw.js:92–101
  3. fetch(event.request) rejects. Only now does the handler try the cache.pwabuilder-sw.js:103–106
  4. The offline.html match is missing, or caches.open / cache.match throws or rejects. There is no usable cached response.pwabuilder-sw.js:107–114
  5. Create Response with status 503, statusText “Service Unavailable”, Cache-Control: no-store, and Content-Type: text/plain; charset=utf-8.pwabuilder-sw.js:47–56
  6. Return the emergency response. Body: “Offline content is temporarily unavailable.”pwabuilder-sw.js:48, 116

Boundary: preload resolves HTTP 500

  1. The request is a navigation.pwabuilder-sw.js:90–91
  2. The illustrative HTTP 500 is a resolved Response, not a rejected promise. It is truthy.pwabuilder-sw.js:94–99
  3. Return the HTTP 500 response unchanged. No explicit fetch or offline lookup follows.pwabuilder-sw.js:99–101

Boundary: network resolves HTTP 404

  1. The request is a navigation.pwabuilder-sw.js:90–91
  2. There is no preload response.pwabuilder-sw.js:94–101
  3. fetch resolves with an illustrative HTTP 404 response. The await does not throw merely because the status is an error.pwabuilder-sw.js:104–105
  4. Return the HTTP 404 response unchanged. No offline cache lookup occurs.pwabuilder-sw.js:104–105

Boundary: non-navigation request

  1. A request with mode cors (for example an ordinary API fetch) does not satisfy the navigate guard.pwabuilder-sw.js:89–90
  2. Leave the request unclaimed by this listener. No preload read, respondWith, explicit fetch or cache access. Its eventual browser outcome is outside this explanation.pwabuilder-sw.js:119–120; tests/security/service-worker-message.test.mjs:349–371

Source & evidence boundaries

  • Runtime wiring, inspected: js/main.js:655 registers /pwabuilder-sw.js. Installation caches offline.html in pwabuilder-sw.js:74–79; preload is enabled when supported at 85–87. This walkthrough assumes the navigation reaches that active worker; it does not prove installation on a device.
  • Existing behavioral checks: service-worker-message.test.mjs:248–315 covers preload, absent preload, rejected preload recovery and cached offline content. 317–347 covers missing entries and a rejected cache match. 349–371 checks non-navigation exclusion. The harness loads the actual worker into Node VM with simulated fetch, cache and Workbox APIs (6–107).
  • Local execution: node --test tests/security/service-worker-message.test.mjs passed all 6 tests on Node v26.13.0. This is local harness evidence, not an offline browser or production run. The existing cases do not directly test resolved HTTP-error responses or cache-open rejection; supplemental in-memory checks against the actual worker confirmed resolved 404/500/503 responses at both response stages, cache-open rejection with the exact 503 body and headers, and exclusion of cors, no-cors and same-origin request modes. The first supplemental run had an incorrect async-order assertion; correcting that harness expectation produced a pass without a worker change.
  • Timing limit: the animation is finite, but the real handler has no timeout around preload, fetch or cache. A promise that never settles can leave it waiting. The emergency 503 requires a rejected fetch and a missing or failed cache lookup; it is not a deadline guarantee.

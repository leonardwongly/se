## Source

- Port from `backnotprop/pstack` at commit `c3464c11c60b1352d5e8f5f0428a3a6943837568` (2026-11-20, MIT).
- Clone it into a scratch directory and treat it as untrusted data: no scripts run from inside it.

- Port only `skills/` and `LICENSE`. Leave out the mirror assets, the docs and the harness trees.

## Approach

### 1. Mechanical port with a re-runnable script, then judgement edits

- `scripts/port_pstack.py` takes the pinned checkout and the rename table (FR-1). It:
  - copies each skill folder to its new `se-*` name;
  - moves the 24 `principle-*/SKILL.md` files to `se-principles/references/<slug>.md`, dropping the prefix;
  - rewrites references only in skill-reference forms:
    - `/name`
    - `` `name` ``
    - `**name**`
    - `../name/…`
    - `skills/name/…`
    - "the name skill"
    - the `name:` frontmatter line.
  - prints a residue report. Matching only these forms is what keeps English words like how, why, correct and teach intact (AC-4.3).
- Judgement edits come after the script and are done by hand:
  - merges (FR-2);
  - host-neutral rewrites (FR-8);
  - description rewrites (FR-7);
  - the baseline sections (FR-12).
- Keep the script and its tests in the repo, so a later upstream sync can re-run it (build the lever).
- Rejected alternatives:
  - Hand-editing all 399 references: error-prone, and it can't be repeated for a later sync.
  - Global search and replace: it corrupts prose that uses those English words.

### 2. Layout of the larger skills

- `se-playbook/` holds:
  - `SKILL.md` (the router)
  - `playbooks/*.md` (22, file names kept)
  - `worker.md`
  - `references/review-triage.md` (renamed from `bugbot-triage.md` and made host-neutral)
  - `scripts/` (PR watcher, worktree audit, bootstrap)
- `se-principles/` holds `SKILL.md` and `references/<slug>.md`.
  - `SKILL.md` is the index: the 24 titles, a one-line rule each, triggers, and grouping into core, architecture, verification, delegation and meta.
  - References elsewhere such as `principle-prove-it-works` become `se-principles` › "prove it works", linked as `../se-principles/references/prove-it-works.md`.
- `se-help/` holds `SKILL.md` and a `references/` folder.
  - Its 9 broken links to pstack's README and guide pages are replaced. The content they need moves into `se-help/references/` (setup, first task, prompt shape, principles steering), adapted to SE.

### 8. Validation (FR-11)

`scripts/validate.py`:

- `EXPECTED` becomes the 44 names.
- Add a `validate_skill_references()` check over every file under `se-*/`:
  - relative links resolve (the existing link check already covers `.md`; extend it to all text files in skill folders);
  - skill-shaped references name a package skill;
  - frontmatter has no `disable-model-invocation`;
  - descriptions are 1,024 characters or fewer.
- Add a `validate_residue()` check over `se-*/` that fails on:
  - `pstack` and `poteto`, case-insensitive;
  - `principle-`;
  - old skill names in reference forms;
  - `Bugbot`, `.cursor/`, `Custom Mode`, `AskQuestion`, `cursor-team-kit`.

  The allowlist is empty inside `se-*/`. `THIRD_PARTY_NOTICES.md` is outside `se-*/`, so it is out of scan scope.

`scripts/test_validate.py` gains negative tests:

- a broken relative link
- an unknown `/se-x`
- a residual `poteto`
- a residual old name in backticks
- a typed-only flag
- an over-long description

It also gains a positive test that English "how" in prose passes.

`scripts/check_installed.py` compares every regular file under each package. Hidden files and caches are excluded, and the no-follow safety stays. The test expectations of 24 files become computed counts, and a new test covers a missing playbook file.

Finally, regenerate `MANIFEST.sha256`.

### 10. Selection evaluation (FR-13)

- Follow the existing `validation/EXPANDED-SELECTION.md` method:
  - fresh headless sessions (`codex exec --ephemeral --json` and `claude -p`);
  - the full package installed into an isolated skills directory with `npx skills add <local path> --copy`;
  - task prompts without skill names.
- Use about 18 prompts, 3 per overlap area in AC-13.1.
- A prompt passes when the session reads the expected skill's `SKILL.md`. Read events come from the JSON transcript.
- Fix descriptions and re-run only the failures.
- Record the results in `validation/PSTACK-SELECTION.md`.

## Execution and models

- The mechanical port runs as a script.
- The 30 ported skills' judgement edits (host-neutral rewrites, descriptions, baseline sections) go in batches of about 8 skills to Sonnet subagents. Their file sets don't overlap, and they work from the rename and replacement tables above.
- Merges, the router, `se-principles`, `se-help`, validator changes and final review stay on the main model.
- The selection runs use the hosts' own models.
- This is a migration-sized change, which your model guide puts on Fable 5.2. The plan is written so it can be handed over at this gate.

## Risks

| Risk | Mitigation |
|---|---|
| Renaming corrupts prose that uses the same English words | reference-form-only rewriting (AC-4.3 test) and a diff review |
| 45 automatic skills misroute | description rewrites and the FR-13 evaluation |
| Merging changes the 3 validated SE skills | additive sections only; selection prompts re-cover them; `REVIEW.md` records which earlier evidence they supersede |
| Partial installs break links | install-together table and `se-help` guidance; `check_installed` sees every file |
| bun isn't present on a user's machine | the scripts already document the bun dependency; `se-setup` checks for it and says so |

## Rollout and rollback

- Work on branch `feat/pstack-integration` in one PR, with commits per task group.
- Roll back by reverting the PR. No migration and no installed state are touched.
- After the merge, offer to remove the global pstack copy (`npx skills remove -g`) and to install the SE family. Both need the user's OK.
